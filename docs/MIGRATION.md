# Migration from the thesis repository

Where the thesis hard-codes its topic, and what becomes configuration:

| Thesis (masterarbeit-nahost) | Becomes |
|---|---|
| `R/01_konfiguration.R`: `laender`, `sprachen`, `medien*` tribbles | `sources.outlets` (+ country/language tables as defaults) |
| `R/01_konfiguration.R`: `zeitraeume`, `gesamt_start/ende`, `kontroll_tage` | `time.*` |
| `R/14_url_sammler.R`: `url_relevanz_regex`, `mc_suchanfrage` | generated from `topic.keywords` |
| `R/40_relevanz.R`: relevance rules | generated from `topic.keywords` + `min_keyword_hits_in_lead` |
| `R/55_frames.R`, `R/60_quellen.R`, `R/70_validierung.R` | thesis-specific analyses: stay in an `analyses/` plug-in folder |
| `nexis/suchplan.csv`, `skripte/nexis_*.py` | `sources.nexis_uni`, search plan derived from outlets + windows |
| `skripte/live_*.py`, `dashboard_js/` | unchanged core; labels from config |
| `systemd/` units | generated by `setup.R` |

## Steps
1. Config loader + schema validation (`R/config.R`, `setup.R`).
2. Replace the constants above by config reads in the thesis repo first (keeps the thesis running), then copy the generic modules.
3. Move thesis-specific analyses into `analyses/`.
4. A toy example (small topic, 3 outlets) that runs end to end in minutes.
5. Documentation for outsiders; licence; make the repo public after the thesis is submitted.

## Workflow
Jede übernommene Stufe ersetzt den Platzhalter in `workflow/Snakefile` durch den echten Aufruf (Reihenfolge der Schritte oben). Als Vorlage für die Cluster-Stufe dient `workflow/` im Thesis-Repository (Export, Hochladen, Slurm-Jobs je Paket, Import).
